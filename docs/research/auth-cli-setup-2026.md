# Auth setup automation boundary (25 September 2026)

**Verdict:** An agent can build either integration after the owner authorizes the relevant account. Firebase is not uniquely manual: its CLI can create a Firebase project, register a web app, and enable Google sign-in. Better Auth is simpler to provision for this existing Vercel + Neon app because it is a self-hosted library, not another cloud project. Neither option eliminates the Google account/brand-verification steps or the need to supply secrets securely. [Firebase CLI reference](https://firebase.google.com/docs/cli), [Firebase Auth provider CLI](https://firebase.google.com/docs/auth/configure-providers-cli), [Better Auth installation](https://better-auth.com/docs/installation), [Google brand verification](https://developers.google.com/identity/verification/authentication-verification).

| Setup item | Firebase Authentication | Better Auth in MyDriveLog |
| --- | --- | --- |
| Project/account | After the owner completes `firebase login` in the intended Google account, an agent can use `firebase projects:create`. If a Google Cloud project already exists, `firebase projects:addfirebase` can attach Firebase. The [Management REST API](https://firebase.google.com/docs/projects/api/workflow_set-up-and-manage-project) also supports project and app setup with authorized credentials. [CLI reference](https://firebase.google.com/docs/cli). | No hosted Better Auth project is needed for the **self-hosted** framework: install the package in the app and connect the existing Neon database. Better Auth's optional managed infrastructure is a separate product. [Installation](https://better-auth.com/docs/installation), [pricing](https://better-auth.com/pricing). |
| Web app/config | `firebase apps:create WEB` registers a web app; `firebase apps:sdkconfig WEB <app-id>` obtains its SDK config. `firebase init` associates a local directory with a project; it does **not** create the remote project. [CLI reference](https://firebase.google.com/docs/cli). | `npx auth@latest init` initializes locally, but its documented database option currently supports **SQLite only**. For Neon/Postgres, configure Better Auth directly, then use `npx auth@latest generate` for schema or `npx auth@latest migrate` with the built-in Kysely adapter. Other adapters require their ORM migration tool. `npx auth@latest secret` generates an app secret. [Better Auth CLI](https://better-auth.com/docs/concepts/cli), [PostgreSQL adapter](https://better-auth.com/docs/adapters/postgresql). |
| Google provider | Current Firebase docs explicitly support `firebase init auth`, a `googleSignIn` entry in `firebase.json`, and `firebase deploy --only auth`. Its CLI configuration covers OAuth **display name**, support email and authorized redirect URIs; the Identity Toolkit Admin [API](https://docs.cloud.google.com/identity-platform/docs/reference/rest/v2/projects.defaultSupportedIdpConfigs/create) also exposes provider configuration with proper IAM. This is provider setup, **not** completion of public brand verification. [Provider CLI docs](https://firebase.google.com/docs/auth/configure-providers-cli), [Firebase Google sign-in](https://firebase.google.com/docs/auth/web/google-signin). | Add the Google provider in the app's Better Auth config and supply `clientId`/`clientSecret` from a Google OAuth client, with the documented callback URI. There is no Firebase provider to enable, but Google OAuth client and consent configuration still have to exist. [Better Auth Google](https://better-auth.com/docs/authentication/google). |
| Google-facing name/logo | Firebase CLI can set a basic `oAuthBrandDisplayName`; its listed auth-provider fields do **not** include a logo, privacy-policy URL, brand publication or verification. Google documents the full Branding page in Google Auth Platform, plus verification and publishing for an external production app that wants its name/logo displayed. This applies to Firebase and Better Auth. Google's docs state **no paid-plan requirement** for this branding workflow. [Firebase provider fields](https://firebase.google.com/docs/auth/configure-providers-cli), [Google setup](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid), [verification](https://developers.google.com/identity/verification/authentication-verification). | Same Google Auth Platform branding/verification requirement. The app's own sign-in UI and OTP emails remain first-party MyDriveLog surfaces. [Google setup](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid), [verification](https://developers.google.com/identity/verification/authentication-verification), [Better Auth Email OTP](https://better-auth.com/docs/plugins/email-otp). |

**Owner handoff:** The owner must choose and authenticate the intended Google/Firebase account (the CLI supports multiple signed-in accounts via `login:add`, `login:list` and `login:use`), approve ownership/domain and support-email details, and complete any Google Auth Platform brand verification/publishing review. An agent can then do the project, code, schema, Vercel environment and provider configuration inside granted access. Secrets—Neon URL, Better Auth secret, transactional-email key and Google OAuth client secret—must go into local/Vercel secret stores, not source control or chat. [Firebase CLI accounts](https://firebase.google.com/docs/cli), [Better Auth installation](https://better-auth.com/docs/installation), [Google verification](https://developers.google.com/identity/verification/authentication-verification).

**Important fit check:** Firebase's built-in passwordless email sign-in for web uses a **clickable email link**, not MyDriveLog's requested typed six-digit email OTP. MyDriveLog can nevertheless use Firebase with a custom OTP flow like the existing Ralph project: verify the emailed code in the app backend, then issue a Firebase custom token. This requires maintaining the OTP logic; Better Auth instead provides an [Email OTP plugin](https://better-auth.com/docs/plugins/email-otp). [Firebase email-link authentication](https://firebase.google.com/docs/auth/web/email-link-auth), [Firebase custom authentication](https://firebase.google.com/docs/auth/web/custom-auth).
